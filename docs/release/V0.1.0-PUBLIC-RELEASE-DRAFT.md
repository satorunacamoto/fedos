## Release title

**FedOS v0.1.0 — first public source release (Closed Pilot)**

## Summary

This is FedOS's first public release of its source repository under
MPL-2.0. FedOS is a local-first, privacy-oriented toolkit for messaging,
commerce, pseudonymous identity, signed credentials, QR proofs, and
offline-verifiable trust, built on Nostr. The one currently shipped
application surface is **FedOS Desktop**, a direct (1:1) end-to-end
encrypted Nostr (NIP-17) messenger for Windows, distributed as an
unsigned installer during a small **Closed Pilot**.

`v0.1.0` marks this repository becoming publicly readable and
buildable from source under an open license — it is **not** a claim
that FedOS has reached Public Beta, passed an independent audit, or is
ready for general use. The `0.x` version number is deliberate.

## Current capabilities

- **Messenger** (`src/os/messenger/`) — the real shipped product. Direct
  1:1 conversations over Nostr NIP-17, NIP-44 v2 encryption inside a
  NIP-59 gift wrap, invitations, search, archive, multi-device pairing,
  identity replacement, and signed deletion. A real Double Ratchet
  implementation exists and is test-covered but is **not** the default
  delivery route — see "Known limitations and caveats" below.
- **Trust** (`src/os/trust/`) — signed envelopes, pseudonymous
  credentials, proof-of-possession, capability grants, offline-verifiable
  subscription entitlements, signed-QR encode/decode, and
  contract-artifact proofs, all verifiable with zero network calls.
  Usable today via a standalone CLI (`npm run trust:issuer`). Not yet
  wired into the packaged desktop app.
- **Commerce** (`src/os/commerce/`) — a real product catalog and
  `PaymentProvider` seam carried forward from FedOS's pre-pivot
  prototype. Not wired into the packaged desktop app.
- **Core** (`src/os/core/`) — identity, cryptography, and settings
  primitives the other capabilities sit on. Live and in production use
  for identity/crypto/settings within the shipped app.

**No mandatory FedOS server or API.** Messaging runs over Nostr relays
you choose; Trust verification is entirely local; the optional FedOS
Official subscription is issued by a human running an offline CLI, not a
hosted activation service.

## Experimental / unaudited caveats

- **No independent security audit has ever been performed.** All
  cryptographic review to date is by this project's own authors.
- **Windows release artifacts are unsigned.** Expect a SmartScreen
  warning on install; this is expected, not a sign of tampering, but it
  also means there is no code-signing chain of trust yet.
- **Forward secrecy is not active for ordinary messages.** The Double
  Ratchet implementation is real and test-covered, but the pilot build
  routes ordinary sends over plain NIP-17, not the ratchet, by default.
- **No anonymity or onion routing.** Relays can observe metadata
  (who is talking to whom, and when).
- **Trust and Commerce are not reachable from the packaged app** — real,
  tested code, but currently exercised only via their own test suites and
  (for Trust) a standalone CLI.
- **No passphrase recovery.** Losing your passphrase means losing your
  data; there is no key escrow or reset.
- Full, current, itemized detail: [`KNOWN_LIMITATIONS.md`](../../KNOWN_LIMITATIONS.md)
  and [`SECURITY.md`](../../SECURITY.md).

## Install / build

```sh
npm ci                       # install from lockfile
npm run build:wasm           # Rust -> WebAssembly core
npm run release:electron-beta   # unsigned installer + portable ZIP
```

Pinned toolchain: Node 24.x, npm 11.12.1, Rust 1.95.0, wasm-bindgen
0.2.126. Full instructions: [`BUILDING.md`](../../BUILDING.md) and
[`docs/pilot/INSTALLATION.md`](../pilot/INSTALLATION.md).

## Release readiness assessment (for the maintainer's decision, not a recommendation to act)

**A `v0.1.0` *source* tag is reasonable to consider** — the repository
already satisfies its own OSS release-surface verifier (8/8 checks:
license, required docs, no forbidden secret paths, no machine-specific
leaks, no embedded issuer key material, required Trust tests present,
required package/build files present, `src/os/oss/` correctly absent)
and its current supported test surface is 100% green (132 files / 1902
tests). The `0.1.0` number itself, under semver convention, already
signals "early, unstable, no compatibility promise," which matches
FedOS's actual Closed Pilot status honestly.

**What `v0.1.0` should *not* be read as, and this draft should not imply
otherwise if published:** a claim that FedOS has passed Public Beta
readiness, an independent security audit, or a code-signing decision.
`ROADMAP.md`'s own "Immediate gate before any wider release" section
still lists an independent security audit as open, unchanged across
every prior review. If a GitHub Release is cut from this draft, keep the
"Closed Pilot" and "no audit" language intact rather than softened for
launch-announcement purposes.

**This arc does not create the tag or the GitHub Release.** That is an
explicit human action, left for the repository owner to take (or not)
after reviewing this draft.
