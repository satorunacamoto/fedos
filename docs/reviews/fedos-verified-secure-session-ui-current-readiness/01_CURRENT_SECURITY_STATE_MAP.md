## Notes for the mega-arc's later phases

- The single biggest overclaiming risk if a "Verified Secure Session" UI were built naively today:
  surfacing a session/conversation-level "Ratchet active" badge from ratchet session persistence
  (Item 5) — this would be **true of storage state but false of actual message routing** for
  every ordinary packaged launch, because the routing gate is a separate, unrelated
  construction-time flag. Any such UI must read `forwardSecrecySelector`/
  `describeFedosForwardSecrecyRoute()` (already computed, already reporting-only, currently
  unconsumed by any UI) rather than session lifecycle state.
- There is currently no way to build a genuinely truthful **per-message** "how was this
  protected" indicator (Item 11) without a new, additive field on the persisted Envelope or import
  record — none exists today to read.
- The "silently auto-accepted old key" Safety Center counter (Item 3) is real, tested, and wired,
  but is guaranteed to always read `0` in the shipped app under its current configuration — it is
  not evidence of anything happening in production today, only of a code path that exists and
  could fire under a different configuration.
- "Cancel" is not a real concept in the Identity Replacement flow (Item 4) — only `accept`,
  `reject`, and `defer` (a near-no-op) exist. Any UI copy using the word "cancel" for this flow
  would not match any real underlying state.
